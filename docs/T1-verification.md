# 页内 T1：macOS 原型验证报告

日期：2026-09-17。结论：已交付可运行的 macOS Apple Silicon 技术原型；macOS 关键编辑链路通过，完整 T1 三端门槛尚未通过。

同日键盘回归补充：下表最初的输入验收依赖粘贴，遗漏了输入层复制只读样式导致的键盘输入失败。该问题已修复并重新进行真实按键验收，详情见 [macOS 键盘输入回归记录](macOS-keyboard-regression.md)。此前交付包不包含本次修复，应使用当前项目重新构建的应用。

## 交付内容

- `PageIn-T1-macOS-arm64.zip`：解压后为 PageIn.app，本机原型，尚未正式签名、公证。
- `PageIn-T1-source.zip`：源码、mise 配置、npm / Cargo 锁文件、夹具、测试与架构文档，不含构建缓存和 node_modules。
- 本阶段支持打开、预览、双击改字、会话撤销/重做、导出新 HTML。持久历史版本、跨重启回退与崩溃恢复未实现，仍属后续 T4。

原应用标识为 io.pagein.spike。验收使用独立的 io.pagein.validation 副本，避免切换用户已打开的实际文件；两者使用相同 Release 可执行文件。若旧原型仍在运行，先正常关闭，再打开本次交付版本。

## 实测环境与构建

Apple M4、16 GiB 内存、macOS 26.6.2（25G83）、arm64、Xcode 26。使用系统 WKWebView，不包含 Chromium / CEF 或 Node 运行时。项目由 mise 固定 Node 24.12.0、Rust 1.92.0；npm 11.6.2；Tauri Rust 2.11.5。

Release 构建成功，TS 类型检查通过，10 项解析测试与 6 项 Rust 测试通过，cargo fmt / Clippy（warnings 视为错误）通过。测试涵盖源位置、UTF-8 / BOM / CRLF / emoji / 实体、混合标签、脚本净化、相对资源、过期版本、补丁保真和越界资源拒绝。

## 已修复的原生问题

1. 禁脚本 iframe 中父层注册的事件在 WKWebView 不执行。实机复现与 [WebKit 218086](https://bugs.webkit.org/show_bug.cgi?id=218086) 一致，采用 [ADR-003](ADR-003-webkit-input-surface.md) 的可信输入层，保留沙箱限制。
2. macOS 默认 Quit 菜单直接结束进程。最终改为自定义菜单发起前端未导出检查，并以显式退出许可标志处理正常退出。

## 当前边界与下一阶段

输入为不超过 5 MiB 的有效 UTF-8 HTML，最多 50,000 个可编辑文字片段。只编辑可可靠映射的纯文本叶元素；混合父元素保持只读，独立子元素可映射。旋转、缩放与竖排保持只读。自定义字体、伪元素、复杂嵌套滚动、空文本再编辑等场景仍需完善。

仅加载原文件所在目录内的允许类型资源，远程资源禁用；依赖脚本渲染的页面、内嵌 frame 不属于本阶段支持范围。同目录资源使用原相对路径导出，移到其他目录时需要保留相应资源布局。

Windows WebView2、Omarchy WebKitGTK / Wayland、真实中文 IME、字体与分数缩放、总进程内存、冷启动 20 次 P95 均未验收。当前没有这两个平台的可执行安装包。补齐这些 T1 验证后再确定进入 T2–T4；不将本报告标为完整产品验收通过。
