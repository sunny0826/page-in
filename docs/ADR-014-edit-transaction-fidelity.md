# ADR-014：编辑事务恢复与文本导出保真

日期：2026-09-26。状态：实现及集成审核完成，自动与 macOS 核心流程验收通过；真实 IME 候选输入仍待验收。见[验证记录](edit-correctness-verification.md)。

## 决策与替代范围

PR 集成基线更新为 c42a4c0。ADR-010 的模块拆分、ADR-011 的隔离动态报告、ADR-012 的全屏焦点和 ADR-013 的 Linux 分发保持不变；下述静态 iframe 约束适用于编辑层。本 ADR 原编号与上游重复，提交 PR 时改为 014。动态预览也需在临时序列化中保留首 LF；唯一源 marker 且确认值为空时，可在重新进入编辑后恢复空 Text 节点，源区间仍使用原始清单。

修复 main@9af26e5 审查发现的四项问题：空文字无法重编、提交拒绝后丢失输入、特殊 HTML 文本上下文导出不一致，以及独立 CSS 变换导致输入层重复缩放。

本 ADR 部分替代 [ADR-003](ADR-003-webkit-input-surface.md) 的“结束输入即移除输入层”：提交必须等待核心确认，失败保留可重试的输入；显式取消恢复已确认文字。细化 [ADR-002](ADR-002-t1-spike.md) 的可编辑范围和源字节补丁编码。单窗口、静态 iframe、父页面可信输入层、原始字节不可变、Rust 权威、会话/修订校验及不覆盖导出保持有效。无需修改运行时、依赖、capability 或发布流程。

映射 Text 节点在空字符串时继续存在；编辑命中层为空片段提供最小命中区域，输入层提供可用的光标尺寸，所有辅助内容都只存在于预览/可信父页面。变换检测覆盖元素和祖先的 transform、translate、rotate、scale、zoom、writing-mode 等影响对齐的条件，无法可靠对齐则保持只读。

raw-text 上下文 xmp、noembed、noframes、plaintext 保持只读。普通 pre/listing 仍可编辑；清单增加可选 `textContext: "html" | "pre-leading"`，缺省按 html 处理。只有源文本紧邻 pre/listing 起始标签时使用 pre-leading。核心导出该上下文的新文字若以 LF 开头，额外输出一个 LF 供 HTML 解析器消耗。原文件已有被解析器忽略的首换行时不再补偿。未修改区间、实体、BOM 和 CRLF 保持原始字节。

共同夹具验证发现，已保留的单独 CR 会与补丁起始 LF 合并。为保留两者的解析语义，补丁前一个原始字节为 CR 时，将新文字的第一个 LF 编码为 `&#10;`；区间外 CR 仍逐字节不变。

## 替代方案与风险

- 全部 pre/listing 设为只读实现简单，但会降低原有可编辑范围，因此只限制不能可靠回写的 raw-text 内容。
- 在 DOM 中加入占位文字能制造命中区域，但可能污染编辑值和导出，因此使用保留的 Text 节点和临时命中几何。
- 提交失败直接恢复旧页面能保留核心一致性，但会丢失本次输入，因此同时保留核心状态与未确认输入缓冲。
- 不采用 DOM 序列化或执行用户脚本来修复兼容性；这些会改变既有数据与隔离边界。

主要风险是并发 finish/begin、失焦、输入法组合期与异步提交相互影响，以及 pre 起始换行补偿重复应用。通过生产辅助模块的事务测试、解析/原生导出交叉用例及真实系统 WebView 验证控制。
